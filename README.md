# 지폭스케줄 생성기 (PM23 생산지폭)

스케줄(주문) → PM23 생산지폭 표(지폭스케줄)를 자동 생성하는 도구.
스캔 PDF를 화면에서 보고 주문을 검수·수정한 뒤 스케줄을 생성, 엑셀로 내려받는다.

## 구조
```
app.py                ← Streamlit UI
jipok/
  constants.py        기준표 상수(코타손실·트림·서비스·보상·LOSS·흡습)
  calc.py             결정형 공식(23요청폭·완스풀N·길이·CP중량·라운딩)
  pack.py             스케줄러(병합·여유분·균등·합권짝수·CP중량11~33)
  models.py           Order / Spool / Row
  pdf_extract.py      PDF 렌더(+보조 OCR)
  excel_io.py         결과 .xlsx 출력
tests/                검증 스크립트·정답
```

## 로컬 실행
```bash
pip install -r requirements.txt
streamlit run app.py
```
브라우저가 자동으로 열린다(기본 http://localhost:8501).

## 배포 (사내 서버 / Streamlit Cloud)
- `requirements.txt`(파이썬)와 `packages.txt`(apt: tesseract OCR)를 함께 둔 채 배포.
- Streamlit Cloud: 저장소 연결 → `app.py` 지정 → 자동 빌드.
- OCR(tesseract)은 보조용. 스캔 화질상 1차 추출만 하고 사용자가 표에서 확정한다.

## Gemini API 키 설정 (⚠️ 절대 저장소에 커밋하지 말 것)
키는 코드에 하드코딩하지 않고 아래 두 경로 중 하나로만 주입한다(`jipok/gemini_parse.py`가 읽음).
- **로컬**: 셸에 환경변수로 설정 — `export GEMINI_API_KEY=발급받은키` (Windows PowerShell은
  `$env:GEMINI_API_KEY="발급받은키"`). 또는 `.streamlit/secrets.toml.example`을 복사해
  `.streamlit/secrets.toml`로 저장하고 키를 채운다(`.gitignore`에 등록돼 있어 커밋 안 됨).
- **Streamlit Cloud 배포**: 대시보드 "Settings → Secrets"에 `GEMINI_API_KEY = "..."` 를
  붙여넣는다. 저장소에는 절대 올라가지 않고 Cloud 서버에서만 보관된다.
- 앱 사이드바의 "Gemini API 키" 입력칸은 **본인이 그 세션에서만 임시로 쓸 때**용이다 —
  여기 입력한 값은 저장되지 않고 위 두 경로(환경변수/Secrets)가 항상 우선이다.
- 저장소를 push하기 전에 `git status`/`git diff`로 `secrets.toml`이나 `.env`가 스테이징돼
  있지 않은지 항상 확인한다. **혹시라도 키를 어떤 파일에건 한 번이라도 커밋했다면, 나중에
  지워도 git 히스토리에 남아있으므로 그 키는 유출된 것으로 간주하고 재발급(rotate)해야 한다.**

## 사용법
1. 사이드바에서 스케줄 PDF 업로드.
2. **Gemini 자동 파싱**(권장): 사이드바에 Gemini API 키 입력 → 모델(gemini-2.5-flash/pro) 선택 →
   "PDF 자동 파싱" 클릭. 헤더(지종·CP·LOT·초지공정길이)와 주문 표가 자동으로 채워진다.
   - API 키는 입력란 또는 환경변수 `GEMINI_API_KEY` 로 제공.
   - 자동 파싱은 보조 수단 — 스캔 화질상 표에서 **반드시 검수/수정**.
   - (수동 입력도 가능: 좌측 원본을 보며 우측 표에 직접 입력)
3. 우측 표에서 주문(정길이·권취·싱글규격·보상) 검수/수정. 23요청폭은 싱글규격으로 자동계산(덮어쓰기 가능).
4. "지폭스케줄 생성" → 결과 표 + 검증(CP중량 11~33.3 / 총길이 창 / 합권 짝수) 확인.
   방식은 세 가지 중 선택: **교차정길이 병합(권장, 신규)** / 여유분 우선 / 완스풀 우선.
5. 엑셀 다운로드.

## 핵심 규칙(요약, 2026-08 CM2최종학습 108LOT 전수대조로 갱신)
- **주문은 항상 23요청지폭 내림차순으로 재번호(순서라벨=폭내림차순 순위)한 뒤 패킹한다**
  (`pack.rank_orders`, `schedule()`이 내부에서 자동 적용). 답지의 "(순서N번)" 라벨은 PDF
  원본 표의 순서 컬럼과 무관하게 이 규칙을 따른다는 것이 108개 LOT 전수 대조로 확정됨.
- 23요청폭 = 싱글규격 + 코타손실(CP44·48=40/55↑=30) + 싱글트림(45), 10단위 내림, 최소 4880.
- 길이: 원지전산=(정길이+보상)×N+1500+300, 초지생산실길이=round100(원지전산+초지서비스), 생산길이=round100(원지전산)×스플수.
  혼합-정길이 스풀은 `calc.wonji_jeonsan_items`(항목별 Σ(정길이+보상)×count)로 일반화됨.
- 완스풀 N: CP중량 ≤ 33.3 최대(2026-08 상향, 종전 33.0). **모든 스풀 CP중량 11~33.3**.
- 보상: 롤포장120/폭변경170/길이변경240, **<10000m=120 + 합권 짝수**.
- **교차-정길이 병합(신규, mode="answer_v2")**: 폭이 같으면 정길이가 달라도 자투리를
  한 스풀에 섞는다(같은 정길이끼리는 여전히 각자 완스풀). `pack.make_spools_crossjeong` 참고.
- 총생산길이 = 초지공정길이 이상(상한은 느슨).
- 자투리·여유분 미세 배치는 작업자 판단 → 생성물은 강한 초안, 검수에서 마무리.

## 스케줄 모드(pack.schedule(mode=))
- `answer_v2` — **교차-정길이 병합 지원(신규, 가장 정확)**. 폭 인접이면 정길이가 달라도 섞는다.
- `answer_o1` — 순서1(또는 첫 비완스풀 주문)은 여유분으로 완스풀 완성, 이후는 순서별 완스풀+자투리병합.
- `answer` — 같은 정길이끼리 완스풀 연속충전(건너뛰기 병합), 교차-정길이는 지원 안 함.
- `loss` / `convenience` / `per_order` — 손율최소/작업편리성/주문당 1행(구버전 호환용).
